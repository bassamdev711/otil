# Hotel Management App

تطبيق Flutter Web لإدارة الفندق، مصمم للعمل محلياً أولاً دون اتصال بالإنترنت. يدعم التطبيق تسجيل الدخول المحلي، إدارة الغرف والحجوزات والعملاء، التقارير الأساسية، وإعدادات المستخدمين والفندق.

## المزايا المنفذة

| المجال | الوظائف |
|---|---|
| المصادقة | تسجيل دخول محلي، كلمة المرور الافتراضية `admin / admin123`، صلاحية مدير النظام |
| التخزين | Hive مع `hive_flutter`، ويستخدم IndexedDB عند التشغيل على الويب |
| لوحة التحكم | إحصائيات الغرف، نسبة الإشغال، الإيرادات، وآخر الحجوزات |
| الغرف | عرض شبكي، حالات شاغرة/مشغولة/صيانة/تنظيف، فلترة، إضافة غرفة وتغيير الحالة |
| الحجوزات | إنشاء حجز، اختيار العميل والغرفة، حساب السعر حسب عدد الليالي، Check-in وCheck-out وإلغاء وطباعة الفاتورة |
| العملاء | إضافة عميل والبحث بالاسم أو الهاتف أو رقم الهوية وعرض عدد الإقامات |
| التقارير | إيرادات، إقامات نشطة، حجوزات معلقة، وملخص ورديات |
| الإعدادات | اسم الفندق، إدارة المستخدمين، وتجهيز موضع Firebase المستقبلي دون تفعيله حالياً |

## التشغيل

بعد تثبيت Flutter، نفّذ الأوامر التالية من مجلد المشروع:

```bash
flutter pub get
flutter run -d chrome
```

لتشغيل التطبيق على جميع أجهزة الشبكة المحلية:

```bash
flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080
```

ثم افتح العنوان التالي من جهاز متصل بالشبكة نفسها:

```text
http://<IP-اللابتوب>:8080
```

## الحساب الافتراضي

اسم المستخدم: `admin`
كلمة المرور: `admin123`

يتم تخزين البيانات محلياً في Hive. بيانات Firebase محجوزة للتفعيل مستقبلاً عبر Feature Flag، ولا يتم الاتصال بخدمة خارجية في النسخة الحالية.

## تحسينات تجربة الغرف والهوية البصرية

واجهة الغرف الآن تحتوي على بحث فوري برقم الغرفة أو النوع أو اسم الضيف، ومرشحات مستقلة للحالة والنوع والطابق، وعدادات واضحة للحالات الأربع، وحالة فارغة عند عدم وجود نتائج، وبطاقة تفاصيل تعرض الضيف الحالي والحجز والتواريخ والسعر وإجراءات تغيير الحالة. هذا النمط مستلهم من ممارسات أنظمة PMS الحديثة التي تربط حالة الغرفة بالتشغيل اليومي والتنظيف والصيانة، بدلاً من عرضها كألوان زخرفية فقط.

تستخدم الهوية اسم «النخبة لإدارة الفندق» وألواناً كحلية وتركوازية ورملية ومرجانية، مع رمز قوس الفندق والباب ونجمة الضيافة. الأصول موجودة في `assets/brand/`، والأيقونات مهيأة للويب في `web/icons/`.

## الأداء والأمان وقابلية الترحيل

يستخدم التطبيق الآن `HotelLocalStore` كحد فاصل بين طبقة الواجهة ومخزن Hive. البيانات الجديدة تُحفظ كسجلات مستقلة بمفاتيح من نمط `collection:id` بدلاً من إعادة كتابة قوائم كبيرة كاملة، مع طابور كتابة يمنع تصادم عمليات الحفظ ومهاجرة تلقائية من البنية القديمة. توجد فهارس ذاكرة للغرف والضيوف والحجوزات النشطة، وتستخدم شاشة الغرف استعلاماً مركزياً مع debounce للبحث.

يُفتح Hive في صندوق مشفر بمفتاح عشوائي محفوظ عبر `flutter_secure_storage` عند توفر منصة أصلية أو HTTPS/localhost، ويتم حذف صندوق النسخة القديمة غير المشفرة بعد الترحيل الناجح. عند تشغيل وضع الشبكة المحلية عبر HTTP، يستخدم التطبيق fallback ثابتاً لتفادي تعطل التشغيل؛ يوصى باستخدام HTTPS عندما تصبح حماية المتصفح مطلباً إنتاجياً. كلمات مرور الحسابات الجديدة تستخدم salt مستقل لكل مستخدم، مع استمرار قبول الحسابات القديمة أثناء الترحيل. توجد حماية من المحاولات المتكررة عبر قفل مؤقت، كما تُفرض الصلاحيات داخل `AppController` لا من خلال الواجهة فقط.

العقد `HotelDataSource` في `lib/data/local/hotel_local_store.dart` هو نقطة الترحيل إلى Firebase: يمكن إنشاء تنفيذ Firestore للعقد نفسه مع إبقاء نماذج البيانات والواجهات دون تغيير.
